# Agent Commons v0.2.0 — release candidate checklist

> This is a **release preparation document**, not proof of a published release.
> Do not create `v0.2.0` until the CI and security gates have been met on the exact tagged commit.

## Highlights

- Browser-based **Local Skill Hub** with responsive catalog, per-agent profiles, optional MCP sync, integrity checks and recovery snapshots.
- Search and inspect **pinned, reviewed public skill metadata**; preview every managed installation, update or deletion.
- Protected central **MCP editor** for creating stdio and HTTP/SSE servers, changing agent routing and removing entries. Existing commands, URLs, environment values and vendor extensions remain private when editing routing.
- **Windows x64 portable ZIP**, with a pinned official Node.js 24 LTS runtime verified against its official SHA-256.
- Real **Chromium QA** across five viewports, plus Node 22/24 on Windows, Linux and macOS.
- Local HTTP hardening: loopback-only binding, CSRF, origin/Host checks, nonce-based CSP, path-safe writes and sanitized HTTP errors.
- Release-time Windows asset publishing workflow and npm OIDC trusted publishing workflow.

## Operator quick start

From source (Node.js >=22):

```bash
npm ci
npm run build
node dist/cli/index.js web
```

The dashboard opens at `http://127.0.0.1:4173`. For Windows, download the Windows portable ZIP **only from the verified release assets** after publication and start `Start-AgentCommons.cmd` after extraction. No Windows service or admin rights are required.

## Known boundaries

- The Skill Hub is local and **unauthenticated**. Do not proxy, tunnel or expose it on the Internet.
- All synchronization remains opt-in, with explicit preview/confirmation and backups where applicable.
- Installed skills are not executed during installation. Reviewed license/source metadata does not certify runtime safety.
- Advanced existing-server edits (commands, URLs and secret references) are still tracked in [#18](https://github.com/neosoda/agent-commons/issues/18) and are deliberately not exposed in the browser.
- Windows portable binaries are not signed. Verify the provided SHA-256.
- npm publication requires GitHub Actions OIDC Trusted Publishing to be configured with the correct npm package and repository workflow identity.

## Release gate (do not skip)

- [ ] The MCP editor PR #20 and release-assets workflow PR #21 are merged into `main`.
- [ ] `package.json` and `package-lock.json` both state `0.2.0`.
- [ ] On the release HEAD: six matrix jobs pass (Windows/Ubuntu/macOS × Node 22/24).
- [ ] On the release HEAD: Chromium browser QA passes, screenshots reviewed and Windows portable build/smoke tests pass.
- [ ] `npm audit --audit-level=high` passes or every high-risk finding is explicitly triaged.
- [ ] `npm pack --dry-run` includes `dist/web`, catalog data, README and license.
- [ ] GitHub Release tag matches the tested `main` commit and package version.
- [ ] After publication, verify ZIP + .sha256 are present on the GitHub Release.
- [ ] Verify the npm version is available and its provenance attestation exists, or clearly mark npm as pending.

## Never do this

Never claim the GitHub ZIP, npm release, or signature exists before its publication and verification.
