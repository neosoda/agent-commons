# Agent Commons v0.5.3 — Noms de skills sans doublon

> Version GitHub pour Windows, Linux et macOS. Gestion locale, sans télémétrie et sans publication npm.

## Corrections

- **Noms de skills alignés sur le catalogue.** Certains skills du catalogue ont un identifiant préfixé (par exemple `ecc-design-system`), mais leur `SKILL.md` d'origine garde un nom générique (`design-system`). Les IA identifient les skills par ce nom : deux skills différents apparaissaient alors sous le même nom dans Codex. À l'installation et à la mise à jour, Agent Commons écrit désormais l'identifiant du catalogue dans le champ `name`. Le reçu d'intégrité enregistre la nouvelle empreinte et conserve l'empreinte d'origine.
- **Nouvelle commande `catalog align-names`** pour les skills déjà installés. Elle fonctionne hors ligne, vérifie d'abord l'intégrité de chaque copie et ignore les copies modifiées. Elle affiche un aperçu par défaut ; avec `--yes`, elle crée un snapshot avant d'écrire.
- **`doctor`** suggère cette commande quand un des skills en collision provient du catalogue.

## Validé sur un vrai poste Windows 11

- `catalog align-names --yes` a aligné `ecc-design-system`, qui reste « intact » à la vérification d'intégrité.
- Codex ne voit plus qu'un seul `design-system`, sans erreur de chargement.
- `doctor` : 0 avertissement.

## English summary

v0.5.3 removes duplicate skill names. Namespaced catalog entries (such as `ecc-design-system`) kept their upstream generic `name` (`design-system`), so clients listed two different skills under one name. Install and update now write the catalog id into the managed copy's `name`, and the receipt records both the new and the upstream blob hashes. The new offline `catalog align-names` command migrates existing installs after an integrity check (preview by default, snapshot with `--yes`), and `doctor` suggests it. On a real Windows 11 profile, real Codex lists a single `design-system` with no load errors, and `doctor` reports no warnings.
