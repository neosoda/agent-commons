## Télécharger et vérifier

Sur Windows PowerShell, placer l'archive ZIP et le fichier `.sha256` dans le même dossier :

```powershell
$zip = "AgentCommons-win-x64-portable.zip"
$expected = (Get-Content "$zip.sha256" -Raw).Trim().Split(' ')[0].ToLowerInvariant()
$actual = (Get-FileHash $zip -Algorithm SHA256).Hash.ToLowerInvariant()
if ($actual -ne $expected) { throw "Checksum invalide : ne pas executer l'archive." }
Write-Host "Archive verifiee : $actual"
```

Extraire **l'intégralité** de l'archive dans un dossier personnel, ouvrir `AgentCommonsPortable` puis `Start-AgentCommons.cmd`. L'interface est locale et **ne doit pas** être exposée derrière un tunnel/proxy.

## Publication des versions suivantes

Le workflow `.github/workflows/release-assets.yml` continue d'attacher les assets Windows aux **releases créées manuellement** via `release.published`. Un workflow créant lui-même la release avec `GITHUB_TOKEN` doit directement joindre les assets : les déclencheurs `release.published` ne sont pas garantis dans ce cas. Conserver l'exigence de CI 6/6, Chromium, portable Windows, checksum vérifié, puis créer un nouveau tag depuis le commit validé.

**npm :** publication du package `@neosoda/agent-commons` non confirmée. Le workflow `publish.yml` n'agit que si la variable `NPM_PUBLISH_ENABLED=true` a été activée par le propriétaire après bootstrap autorisé du scope, 2FA et configuration du Trusted Publisher. Ne jamais confondre GitHub Release et npm.
